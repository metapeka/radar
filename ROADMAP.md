# ROADMAP

> Куда движется проект и что считается готовым. Обновлять при смене приоритетов.

## Рамки

- Статический сайт на GitHub Pages, без сервера, аккаунтов и аналитики.
- Каждое утверждение — с источником, датой и уровнем уверенности.
- Автоматика собирает черновики; публикует человек после проверки.
- Материал защитный: без инструкций по атакам и без чужих персональных данных.

## Три оси

1. **Источники** — что мониторим.
2. **Покрытие** — какие сервисы и платформы описываем.
3. **Пользователь** — что он может сделать сам: чек-лист, сценарий, проверка.

## Этап 0. База доверия

**Цель:** читатель видит, когда страница проверена и какие источники живы.

- [x] Дата «проверено» на каждой странице.
- [x] Страница «Здоровье источников»: последняя успешная проверка, статус, что сломалось.
- [x] RSS/Atom для сводки и обновлений.
- [x] CI-проверка внутренних и внешних ссылок.
- [x] Issue-шаблон «Новый источник».
- [x] LICENSE: текст CC BY-SA 4.0, код MIT (решение мейнтейнера).

**Готово, когда:** у каждой страницы есть дата проверки, битых ссылок нет, статус источников виден публично.

**Зависимости:** нет. Это первый шаг.

## Этап 1. Каталог сервисов

**Цель:** добавлять сервисы данными, а не копипастой страниц.

- [x] `site/data/services.json`: сервис, платформа, пункты, приоритет, версия, источник, дата проверки.
- [x] Генератор таблиц и страниц из JSON.
- [x] 10–15 сервисов: мессенджеры, почта, браузеры, менеджеры паролей, роутеры.
- [x] Миграция существующих страниц без потери текста.
- [x] Проверка: одна запись JSON → одна строка таблицы и один блок чек-листа.

**Готово, когда:** новый сервис добавляется правкой JSON и ревью, без новой вёрстки.

**Зависимости:** этап 0, чтобы у записей была дата проверки.

**Можно сейчас:** да. Внешних сервисов не нужно, вся работа внутри сборки.

**Порядок:** схема и валидатор → генератор → миграция по одной странице (первой — WhatsApp) → остальные. Пункты переносятся дословно, diff сверяется: миграция не должна терять текст.

**Сделано:** схема, генератор и каталог; 15 сервисов, 156 пунктов — 4 мессенджера, 5 платформ, 3 менеджера паролей, почта, браузер, роутер. Этап закрыт.

## Этап 2. Личные инструменты

**Цель:** не «читайте 100 пунктов», а «вот ваши 10».

- [x] Раздел «Семья»: телефон за 15 минут, определение устройства, пуши и обман, чек-лист для родителя. Страницы статические, из уже проверенных материалов.
- [ ] Опросник: роль, профиль риска, платформы → персональный чек-лист.
- [ ] Мастер инцидента: угон аккаунта, изъятие устройства, утечка, доксинг.
- [ ] Всё считается в браузере; никаких аккаунтов и отправки данных.

**Готово, когда:** инструменты работают без JS-бэкенда, не логируют ввод и объясняют каждый пункт.

**Зависимости:** этап 1, чтобы чек-листы были данными.

**Можно сейчас:** да, после этапа 1.

**Блокер:** решён — бюджет JS поднят до 25 КБ (DESIGN §8), `app.js` 15,9 КБ укладывается с запасом. При добавлении инструментов следить за размером.

## Этап 3. Утечки

**Цель:** помочь проверить себя, не становясь хранилищем чужих данных.

- [x] Страница «Проверка утечек»: HIBP, Pwned Passwords, Mozilla Monitor, Password Checkup — ссылками, без форм и запросов.
- [ ] Политика: не хранить пароли, не публиковать дампы, не перепродавать доступ.
- [ ] Юридическая проверка текста про чужие данные (152-ФЗ).

**Готово, когда:** читатель может проверить себя по ссылкам, а сайт ничего не собирает и не отправляет.

**Зависимости:** нет.

**Решено:** отправка данных из инструментов не делается — ни виджет, ни CLI с внешним API. Это подрывает доверие: гарантий, что сторонний сервис или репозиторий не сохранит ввод, у статического сайта нет. Проверки — только ссылками.

**Не планируется:** мониторинг домена — требует сервера и обработки чужих данных.

## Этап 4. Распространение

- [ ] Английская версия ключевых страниц.
- [ ] Партнёрства: Access Now, CPJ, Front Line Defenders, локальные НКО.
- [ ] Публичные JSON-датасеты: сравнение мессенджеров, CVE, чек-листы.
- [ ] CITATION.cff и правила переиспользования.
- [ ] Регулярный обзор раз в квартал.

**Готово, когда:** материалы можно цитировать и переиспользовать по понятной лицензии, есть внешние читатели и партнёры.

**Дёшево сейчас:** `CITATION.cff` и публичные JSON-датасеты — данные уже есть, нужны схема и стабильные URL.

**Дорого:** английская версия — около 25 страниц, плюс переключатель языка и `hreflang` в сборке. Начинать с ключевых страниц.

**Не код:** партнёрства и квартальный обзор. Обзор уже поддержан `tools/check_verified.py` — он показывает просроченные даты.
