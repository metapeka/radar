# Провенанс источников

Зачем: зафиксировать, **что именно мы прочитали, когда и в каком виде** — чтобы ссылка на статью не зависела от того, удалят её, перепишут или перенесут.

Манифест публичный и лежит в репозитории. Полные снапшоты — приватные, в `provenance/.private/`, и в git не попадают.

## Что публично, что приватно

| Объект | Где | Публично |
|---|---|---|
| `sources.json` — URL, автор, дата, хеш, размер, статус | репозиторий | да |
| `README.md` — правила | репозиторий | да |
| Снапшоты HTML/PDF | `provenance/.private/` | нет, gitignored |
| Сборка сайта | `docs/` | да, но провенанс туда не входит |

Хеш в манифесте доказывает, что у нас есть файл с такими байтами. Сам файл читателям недоступен — это сознательный компромисс между доказуемостью и авторским правом.

## Структура

```
provenance/
  README.md        эти правила
  sources.json     манифест: по записи на источник, история снапшотов внутри
  .private/        снапшоты (не коммитятся)
tools/
  snapshot.py      снять источник, обновить манифест
  verify_provenance.py  проверить хеши и приватность
```

## Как добавить источник

1. Добавить запись в `provenance/sources.json`:

```json
{
  "id": "habr-author-2026-01-01",
  "url": "https://example.org/article",
  "title": "Название",
  "author": "Автор",
  "publisher": "Издание",
  "published": "2026-01-01",
  "kind": "article",
  "lang": "ru",
  "note": "Что именно берём из этого источника",
  "snapshots": []
}
```

2. Снять снапшот:

```bash
python3 tools/snapshot.py --id habr-author-2026-01-01
```

3. Проверить:

```bash
python3 tools/verify_provenance.py
```

4. Закоммитить **только манифест**. Файл из `.private/` не добавлять.

## Как снять заново

```bash
python3 tools/snapshot.py --all          # новая версия всех источников
python3 tools/snapshot.py --id <id>      # новая версия одного
python3 tools/snapshot.py --dry-run      # показать, что будет снято
```

Новая версия **не перезаписывает** старую: файл получает метку времени, в манифест добавляется ещё одна запись в `snapshots`. История остаётся в JSON и в git.

## Правила

1. **Снапшот — сырые байты ответа.** Никакой очистки HTML, удаления рекламы и «улучшений». Иначе хеш перестаёт что-либо значить.
2. **Один источник — один `id`.** Не переиспользовать ID для другой статьи.
3. **Ничего не перезаписывать.** Изменилась статья — новая запись с новой датой; в `note` можно указать, что изменилось.
4. **Время — UTC.** Поле `retrieved` заполняет скрипт.
5. **Статус — HTTP-код.** `200` — снято; `403`, `451`, таймаут — тоже факт, он остаётся в манифесте.
6. **Хеш — SHA-256 от сырых байт.** Для PDF — от файла, не от распакованного текста.
7. **Проверять перед коммитом.** `verify_provenance.py` падает, если хеш не сошёлся или приватный файл попал в git.
8. **Коммиты и теги — подписывать.** `git commit -S`, `git tag -s provenance-YYYY-MM-DD`. Без подписи дата коммита — только заявление автора.
9. **`provenance/.private/` — в резервную копию.** Git её не хранит; при потере машины снапшоты исчезнут, останутся только хеши.

## Если статья исчезла или изменилась

- Исчезла: запись и хеш остаются. В `note` добавить архивную ссылку (Internet Archive, archive.today), если она есть.
- Изменилась: снять новую версию, старую не трогать. Расхождение — самостоятельный факт, его можно описать на странице.
- Появилась новая версия отчёта: новый `id` или новая запись, если это тот же документ.

## Авторское право

- В публичный репозиторий полные тексты **не попадают**. Приватная копия нужна для проверки цитат и фиксации состояния источника.
- Цитирование в вики — в объёме, оправданном целью, с указанием автора и источника (ст. 1274 ГК РФ). Атрибуция не заменяет разрешение на полную перепубликацию.
- По требованию правообладателя файл удаляется. Хеш и метаданные остаются: они не являются объектом авторского права.
- Это не юридическая консультация. Для публичного архива нужна отдельная проверка.

## Ограничения

- Хеш подтверждает целостность наших байт, но **не** то, что источник отдал именно их. Цепочка — URL, время, статус, заголовки, хеш; при споре нужна независимая копия или подпись.
- Читатель не может проверить приватный снапшот. Он видит только хеш и метаданные. Для внешней проверки нужен публичный архив или разрешение правообладателя.
- Git делает изменения **заметными**, но не невозможными: force-push переписывает ветку. Подписанные теги и внешние копии — единственная страховка.
- Динамические страницы (Habr, новости) меняются: хеш фиксирует состояние на момент снятия, а не «канонический текст».

## Чего не делать

- Не коммитить `provenance/.private/`.
- Не редактировать снапшот «чтобы было читаемо».
- Не хранить полные тексты в `docs/` и на GitHub Pages.
- Не считать наличие хеша доказательством авторства или правомерности публикации.
