# RISK-MODEL.md — как распределяются профили

Документ для разработки: правило, по которому пункт попадает в «Обычный», «Повышенный» или «Целевой» профиль. Нужен, чтобы база не превратилась в список «всё важно» и чтобы решения можно было оспорить.

## 1. Три уровня противника

Профиль — это не «насколько вы осторожны», а **от кого вы защищаетесь**.

| Уровень | Кто атакует | Примеры | Кому актуально |
|---|---|---|---|
| **T0 — массовый** | Криминал, автоматика | Стилеры, фишинг, угон по коду, фейковые приложения | Всем |
| **T1 — адресный** | Криминал с целью, конкуренты, инсайдеры | Целевой фишинг, SIM-swap по заказу, BEC, кража сессии у руководителя | Деньги, роль, доступ |
| **T2 — государственный** | Спецслужбы, mercenary spyware, принуждение | Pegasus/Graphite, изъятие устройства, требования к облаку | Журналисты, правозащитники, чиновники |

Профиль = набор уровней, которые человек обязан пережить:

- **Обычный** — T0 плюс дешёвая гигиена против T1.
- **Повышенный** — T0 + T1.
- **Целевой** — T0 + T1 + T2.

## 2. Паспорт пункта

У каждого действия — пять характеристик. Не «оценка на глаз», а ответы на конкретные вопросы.

| Поле | Значения | Вопрос |
|---|---|---|
| `threat` | T0 / T1 / T2 | Против кого это работает? |
| `impact` | 1–3 | Что теряем без этого: метаданные → аккаунт → устройство |
| `effect` | 0–3 | Насколько помогает: 0 не помогает, 3 закрывает класс атак |
| `cost` | 0–3 | Чего стоит: 0 незаметно, 3 ломает сценарий или требует второго устройства |
| `skill` | 0–3 | Нужны ли знания: 0 всем, 3 только специалисту |

## 3. Правило размещения

Решает не «важность», а **цена**. Именно поэтому обычный профиль не тонет в восьмидесяти пунктах.

| Условие | Куда | Пример |
|---|---|---|
| `threat = T0`, `cost ≤ 1` | Обычный | 2SV-пароль, E2EE-бэкап, PIN на SIM |
| `threat = T0`, `cost = 2` | Обычный, помечен «опционально» | Блокировка приложения, скрытие превью |
| `threat = T1`, `cost ≤ 2` | Повышенный | Отказ от облачных бэкапов, ревизия автозагрузки, второй канал для денег |
| `threat = T1`, `cost = 3` | Целевой | Отдельный номер и устройство для работы |
| `threat = T2` | Целевой, всегда | Lockdown Mode, MVT, отказ от SMS, физическая гигиена |

Проверка на существующих пунктах:

| Пункт | threat | cost | Итог |
|---|---|---|---|
| Пароль 2SV + passkey | T0 | 1 | Обычный |
| E2EE-бэкап WhatsApp | T0 | 1 | Обычный |
| Advanced Chat Privacy | T1 | 1 | Обычный |
| Проверка автозагрузки раз в квартал | T1 | 2 | Повышенный |
| Отказ от облачного бэкапа | T1 | 2 | Повышенный |
| Lockdown Mode | T2 | 2 | Целевой |
| MVT-проверка | T2 | 3 | Целевой |
| Отдельное устройство | T2 | 3 | Целевой |

## 4. Три правила, которые важнее таблицы

1. **Предупреждения не скрываются никогда.** Блок «ключ бэкапа невосстановим» виден всем: это не мера, а факт с последствиями.
2. **Сомневаешься — показывай в обычном.** Скрывать дешёвую меру хуже, чем показать лишнюю. Скрывать можно только дорогое: требует устройства, root, отказа от функций или навыков.
3. **Профиль выбирает пользователь.** Мы не угадываем по косвенным признакам.

## 5. Как это устроено в разметке

Блок помечается fenced div:

```markdown
::: {.profile .elevated}
### Что добавить при повышенном профиле
- ...
:::
```

Допустимые классы: `elevated`, `targeted`. Вложенность не поддерживается. Блок остаётся в HTML всегда и скрывается CSS — поэтому поиск, печать и читалка без JavaScript его видят.

## 6. Проверки при сборке

- Класс профиля только из списка `elevated` / `targeted`.
- У блока есть заголовок `###` — иначе в оглавлении появится безымянный пункт.
- Блок не содержит предупреждений о рисках (это проверяется глазами на ревью, автоматически — нет).

## 7. Как добавить новый пункт

1. Определить `threat`: против кого атака.
2. Оценить `cost`: что человек теряет, если сделает.
3. Посмотреть в таблицу размещения и выбрать профиль.
4. Если пункт спорный — пометить `disputed` и оставить в обычном профиле до решения.
5. Записать изменение классификации отдельным коммитом с причиной.

## 8. Чего эта модель не делает

- Не измеряет «вероятность взлома»: таких данных нет и они не появятся.
- Не учитывает бюджет: «купить второе устройство» может быть недоступно, и это нормально — профиль рекомендательный.
- Не заменяет здравый смысл: если человек знает, что ему угрожают, он включает целевой профиль независимо от рубрики.
