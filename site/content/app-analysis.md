# Анализ приложений

> Как понять, что приложение реально собирает и куда отправляет, не веря ни маркетингу, ни чужим разборам. Методика для Android и iOS на собственном устройстве.

## Рамка

Анализируется **свой** экземпляр приложения на **своём** устройстве с **своей** учётной записью. Цель — понять сбор данных, а не обойти защиту чужого сервиса. Юридические границы — в конце страницы.

## Android: пайплайн

### Шаг 0. Идентификация артефакта

```
sha256sum app.apk
aapt2 dump badging app.apk | head -20
aapt2 dump permissions app.apk
apksigner verify --print-certs app.apk
```

Фиксируем: package, versionName, versionCode, targetSdk, источник (RuStore / Play / APKPure), хеш, отпечаток сертификата. Без этого результат невоспроизводим.

### Шаг 1. Статика

| Этап | Инструмент | Что получаем |
|---|---|---|
| Манифест | apktool 3.x | Точный XML: разрешения, `exported`, `networkSecurityConfig`, `debuggable` |
| Код | jadx 1.5.x | Java/Kotlin, поиск SDK, URL, ключей |
| Обзор | MobSF 4.6.x | Сводный отчёт, SBOM, список трекеров |
| Трекеры | Exodus Privacy | Сопоставление классов с каталогом трекеров |
| Нативные | Ghidra 12.x | `.so`, JNI, кастомный pinning |

Что искать в коде: `okhttp3`, `Retrofit`, `Firebase`, `appsflyer`, `myTracker`, `com.yandex.*`, `ru.*` SDK, `Settings.Secure.ANDROID_ID`, `getInstalledPackages`, `QUERY_ALL_PACKAGES`.

### Шаг 2. Динамика без root

```
adb shell dumpsys package <pkg> | grep -E 'userId|versionName'
adb shell dumpsys netstats detail | grep -A2 "uid=<uid>"
adb shell dumpsys activity services <pkg>
adb shell dumpsys jobscheduler | grep <pkg>
adb logcat --uid=<uid> -v threadtime > logcat.txt
```

`netstats` — самый быстрый способ ответить «ходит приложение в сеть или нет»: сравниваем `txBytes` до и после 5 минут фона. Если растёт, а перехват пуст — трафик идёт мимо.

### Шаг 3. Перехват

| Инструмент | Режим | Ограничение |
|---|---|---|
| PCAPdroid | VpnService, без root | Даёт pcap + привязку «пакет → UID приложения»; QUIC не расшифровывает |
| mitmproxy 12.x | `--mode wireguard` | UDP поддерживается, root не нужен |
| mitmproxy | `--mode regular` | Приложения часто игнорируют системный прокси |
| mitmproxy | `--mode transparent` | Только TCP, сложная настройка |

Ключевая развилка — определяется за пять минут:

1. `netstats` не растёт → приложение не ходит в сеть.
2. Растёт, PCAPdroid пуст → трафик мимо захвата (другой интерфейс, VPN внутри).
3. PCAPdroid видит, mitmproxy нет → приложение не использует системный прокси: переходить на WireGuard-режим.
4. mitmproxy видит, но TLS-ошибка → user CA не доверяется (Android 7+), нужен системный CA или pinning-обход на своём устройстве.
5. Видит и расшифровывает → собрали то, что нужно.

### Шаг 4. Хуки — только при необходимости

Frida + objection требуют либо root, либо пересборки APK с Gadget. Пересборка меняет подпись, а значит ломает Play Integrity и любые проверки целостности — это не «недостаток метода», а его цена.

## iOS: что реально возможно

| Возможность | Без джейлбрейка | С джейлбрейком |
|---|---|---|
| Info.plist, Privacy Manifest, entitlements | да | да |
| Список фреймворков и SDK | да | да |
| Чтение кода (Mach-O `__TEXT`) | нет: FairPlay-шифрование | да, после расшифровки |
| Прокси и TLS | да, где нет pinning | да |
| Frida/objection | только своя debug-сборка | да |
| Дамп памяти, sandbox | нет | да |

Практический вывод: без джейлбрейка вы всё равно получаете 80% ответа — Privacy Manifest, entitlements, список SDK, домены из App Privacy Report и трафик там, где нет pinning.

### Инструменты

```
plutil -convert xml1 -o - Payload/App.app/Info.plist
plutil -convert xml1 -o - Payload/App.app/PrivacyInfo.xcprivacy
codesign -d --entitlements :- Payload/App.app
otool -l Payload/App.app/App | grep -A5 LC_ENCRYPTION
strings -a -n 6 Payload/App.app/App | grep -E 'https?://'
```

`cryptid=1` в `LC_ENCRYPTION_INFO_64` означает, что код зашифрован. Это не «нет данных» — это граница метода.

### Apple как источник

- **App Privacy Report** (Настройки → Конфиденциальность и безопасность): домены по приложениям за 7 дней и доступ к датчикам. Карта, но без payload.
- **Privacy Manifest** — декларация разработчика. Ценность в сверке: заявлено одно, в трафике другое.

## Что фиксировать в отчёте

```
Приложение, версия, платформа, ОС:
Источник и SHA-256:
Разрешения (все / опасные / избыточные):
Компоненты: exported, networkSecurityConfig, debuggable
Домены: список, протокол, частота, размер
Телеметрия: поля, идентификаторы, заголовки
Фон: WorkManager/JobScheduler/services, периодичность
Что не удалось увидеть и почему (QUIC / pinning / native):
```

Последняя строка — самая важная. Отчёт без списка слепых зон вводит в заблуждение.

## Пределы метода

- **QUIC/HTTP3**: TLS-прокси не видит; блокировка UDP/443 заставляет приложение уйти на TCP, но меняет наблюдаемую картину.
- **Certificate pinning**: без модификации приложения или root не обходится; на iOS — только джейлбрейк.
- **Собственная криптография поверх TLS** (WhatsApp, Telegram): видны метаданные, не содержимое.
- **Обфускация и RASP**: имена классов и строки могут быть скрыты; детекторы Frida ломают динамику.
- **Play Integrity / App Attest**: пересобранный клиент виден серверу по дизайну.
- **Серверная сторона** не анализируется вообще: вы видите только то, что клиент отправил.

## Правовые границы

- Только свои устройства и аккаунты; перехват чужого трафика — вне рамок.
- Перехваченный трафик может содержать персональные данные третьих лиц → 152-ФЗ, минимизация и обезличивание.
- Модификация чужого приложения и распространение сборки — отдельная история с отдельными рисками.
- ToS приложений и магазинов может запрещать реверс-инжиниринг; для собственного экземпляра риск иной, чем для публикации.
- Не публикуйте device ID, IP, токены и содержимое переписки.

Это не юридическая консультация. При корпоративном использовании — согласование с юристом и службой безопасности.
