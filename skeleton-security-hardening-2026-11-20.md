# Скелет: защита личных данных и мессенджеров (macOS · Windows · Linux · iOS · Android)

**Версия:** 0.1 (каркас) · **Дата:** 20 ноября 2026
**Назначение:** структура будущего руководства и набора чек-листов. «Мясо» добавляется по разделам, каркас фиксирует границы, порядок и формат.

---

## 0. Как устроен документ

Три уровня детализации — не смешивать:

| Уровень | Что это | Кому |
|---|---|---|
| **L0 — модель** | Слои, угрозы, принципы. Меняется редко | Всем, читается один раз |
| **L1 — чек-лист** | «Проверить / включить / выключить», с приоритетом и ожидаемым результатом | Владелец устройства, раз в квартал |
| **L2 — процедура** | Пошагово с командами, путями, скриншотами, разбором ложных срабатываний | Тот, кто реально чинит |

Правило: L2 не пишем, пока не готов L1. Иначе получается справочник команд без приоритетов.

## 1. Слои защиты

```
[6] Реагирование        — что делать, когда уже случилось
[5] Мониторинг          — базовая линия, обнаружение изменений
[4] Сеть                — Wi-Fi, DNS, VPN, роутер, captive portal
[3] Приложение          — мессенджер: аккаунт, сессии, бэкапы
[2] ОС                  — права, песочница, шифрование, обновления
[1] Устройство          — загрузка, прошивка, физический доступ
[0] Аккаунт             — номер, почта, 2FA, восстановление
```

Ключевая мысль каркаса: **80% реальных инцидентов закрываются на слоях 0 и 3**, а не на слое 1. Поэтому порядок наполнения — снизу вверх по важности, а не по «железу».

### 1.1 Принципы (не обсуждаются, применяются)

1. **Два независимых фактора на аккаунт.** Пароль + passkey/аппаратный ключ. SMS — резерв, не основа.
2. **Разделение идентичностей.** Личное ≠ рабочее ≠ «для регистраций». Отдельные профили ОС и отдельные браузерные профили.
3. **Минимум прав.** Приложению не нужен Full Disk Access / Accessibility, если оно не делает то, что без этого невозможно.
4. **Шифрование в покое по умолчанию.** Диск, бэкапы, архивы артефактов.
5. **Не доверять «зелёной галочке».** Отсутствие индикаторов ≠ отсутствие компрометации.
6. **Один канал — не канал.** Проверка личности по второму каналу при любых просьбах о деньгах/кодах.
7. **Сбор отдельно, анализ отдельно.** Артефакты собираются локально, анализируются офлайн.

## 3. Шаблон чек-листа

Единый формат для всех платформ. ID строится как `<платформа>-<слой>-<номер>`.

| Поле | Смысл |
|---|---|
| ID | `mac-s2-01` — стабильный, не меняется при правках |
| Действие | Императив: «Включить FileVault» |
| Где | Точный путь в UI и/или команда |
| Результат | Как понять, что сработало (что должно быть видно) |
| Приоритет | P0 — без этого нет смысла в остальном; P1 — важно; P2 — гигиена |
| Ломает | Что перестанет работать |
| Проверено | Дата и версия ОС, на которой проверяли |

**Пример заполненной строки (эталон формата):**

| ID | Действие | Где | Результат | P | Ломает | Проверено |
|---|---|---|---|---|---|---|
| `mac-s2-01` | Включить FileVault | System Settings → Privacy & Security → FileVault | Том шифруется, recovery key сохранён вне Mac | P0 | Автозагрузка без пароля | 26.x, 2026-11 |

Правило качества: строка без «Результат» и «Ломает» в документ не попадает.

## 13. Глава: диагностика с помощью AI — что возможно

Отвечает на вопрос «можно ли подключить устройство к AI, чтобы он сам расследовал».

### 13.1 Главное различие
Устройство **не подключается к AI**. К AI подключается **результат сбора с устройства**. Всё остальное — либо агент с заранее выданными правами, либо удалённый шелл.

### 13.2 Четыре модели

| Модель | Что реально возможно | Что нужно | Риск |
|---|---|---|---|
| (a) AI пишет скрипты, вы запускаете локально | Полный сбор, но AI видит только вывод | Запустить, отфильтровать чувствительное | Утечка того, что попало в вывод |
| (b) Read-only агент с allowlist | Чтение состояния в песочнице | Настроить правила и sandbox | Ограничен правами пользователя |
| (c) Офлайн-анализ артефактов | Разбор бэкапов, sysdiagnose, androidqf, osquery | Извлечь и передать архив | Архив целиком чувствителен |
| (d) Полный remote shell | Всё, что позволяет ОС | Админ-доступ и доверие каналу | Максимальная экспозиция |

Рейтинг «польза / риск» для личного устройства: **(c) > (a) > (b) > (d)**.

### 13.3 Что AI не сможет никогда
- [ ] Читать TCC.db / Keychain / реестр / `/proc` без прав на самом устройстве
- [ ] Смотреть память чужого процесса на современных ОС
- [ ] Найти имплант ниже ОС или закладку в прошивке
- [ ] Доказать отсутствие компрометации
- [ ] Обнаружить mercenary spyware по «симптомам» (нагрев, батарея, трафик)

### 13.4 Границы и правила
- [ ] Согласие владельца устройства; для рабочего — политика организации
- [ ] 152-ФЗ: артефакты с ПДн; трансграничная передача — отдельный риск
- [ ] Не отправлять в облако дампы памяти, ключи, переписку
