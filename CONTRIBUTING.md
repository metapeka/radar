# Как участвовать

Спасибо, что хотите помочь. Проект держится на проверяемых фактах и на том, что каждое изменение можно проследить.

## Быстрый старт

Нужны Python 3 и pandoc.

```bash
git clone https://github.com/metapeka/whatsapp-security-research.git
cd whatsapp-security-research
python3 tools/build_site.py        # собрать docs/
python3 tools/verify_provenance.py # проверить хеши источников
```

Локальный предпросмотр:

```bash
cd docs && python3 -m http.server 8000
```

## Структура

```
site/content/*.md      исходники страниц
site/template.html     общий шаблон
site/assets/           стили и поиск
tools/build_site.py    сборка docs/
tools/snapshot.py      приватный снапшот источника
tools/collect_digest.py черновик недельной сводки
provenance/            манифест и правила фиксации
docs/                  опубликованный сайт
```

## Правила страницы

1. Первая строка — `# Заголовок`, затем цитата-лид.
2. Действия — с приоритетом P0 / P1 / P2, а не общими советами.
3. У каждого действия — версия и ссылка на первоисточник.
4. Статусы — словами: подтверждено / один источник / оценка / не найдено.
5. Предупреждения о риске потери данных не скрываются ни в одном профиле.
6. Таблицы — до 4 колонок; внутри `<details>` — без `h3`, чтобы не раздувать оглавление.
7. Страница должна читаться без CSS и JavaScript: смысл только в тексте.

Подробно — в [DESIGN.md](DESIGN.md). Цель и критерий готовности — в [GOAL.md](GOAL.md).

## Источники и провенанс

- Новый источник добавляется в `provenance/sources.json`.
- Полный снапшот снимается командой `python3 tools/snapshot.py --id <id>` и остаётся в `provenance/.private/`.
- Приватные снапшоты **не коммитятся**.
- Перед PR: `python3 tools/verify_provenance.py`.

Правила — в [provenance/README.md](provenance/README.md).

## Недельная сводка

Workflow `.github/workflows/digest.yml` по понедельникам собирает CISA KEV и NVD и открывает Issue-черновик. Автоматика не публикует ничего сама.

Порядок:

1. Проверить каждую строку по первоисточнику.
2. Убрать шум и то, что не меняет рекомендацию.
3. Перенести 3–6 строк в `site/content/digest.md`.
4. Обновить `site/content/updates.md`.
5. Снять снапшот источника.

## Pull request

- Одна логическая правка на PR.
- В описании — что меняется и почему.
- Ссылка на источник и дата.
- `python3 tools/build_site.py` проходит.
- `updates.md` обновлён.
- Дата в `site/data/verified.json` обновлена, если менялись факты; `python3 tools/check_verified.py` проходит.
- Приватные снапшоты и секреты не добавлены.

Шаблон PR подставится автоматически.

## Чего не принимаем

- Инструкции по проведению атак, даже «для исследования».
- Утверждения без источника или с источником-пересказом вместо первоисточника.
- Полные тексты чужих статей в публичном репозитории.
- Персональные данные из чужих устройств и переписок.
- Рекламу, партнёрские ссылки и рейтинги «лучший мессенджер».

## Лицензия

Лицензия пока не выбрана. До её появления не перепубликовывайте тексты целиком; цитирование с указанием источника и ссылкой приветствуется. Если нужна ясная лицензия для текста и кода — это отдельное решение мейнтейнера.
